Confirmado como seguro (não precisou de fix): sem SQL injection, sem segredo hardcoded além do JWT já citado, upload valida mimetype/tamanho no servidor (não só no client), sem caminho de escalação de privilégio pra `UsuarioIsPlataformaAdmin` via API, JWT expira corretamente. > **Logging estruturado implementado em 2026-08-04** (`winston`) — item removido da seção Produto. `backend/utils/logger.ts` (JSON em produção, colorizado em dev, nível via `LOG_LEVEL`) + `backend/middlewares/request-logger.middleware.ts` (log de toda requisição HTTP com `requestId`, devolvido também em `X-Request-Id`) + handler global de erro (`Server.ts`) e `uncaughtException`/`unhandledRejection` (que não existiam) migrados pro logger. **Deliberadamente não tocado:** os milhares de `console.log("🟣 Service.metodo()")` espalhados pelo resto do código — são rastro de execução, não observabilidade de produção; trocar todos é um projeto à parte, de valor marginal e alto risco de diff. **Bug real descoberto como efeito colateral:** ao testar o boot com o `JWT_SECRET` sem fallback (fix da rodada de segurança anterior), o servidor quebrava com "JWT_SECRET não está definido" mesmo com a variável presente no `.env` — causa raiz: TypeScript/tsx sempre hoisteiam `import` pro topo do arquivo compilado, então `dotenv.config()` em `app.ts` (mesmo escrito "antes" de `import Server`) na prática rodava **depois** de todo o grafo de módulos já ter sido carregado, incluindo `JwtService`. Isso sempre existiu — só nunca quebrou nada porque o fallback hardcoded mascarava o problema (ou seja: é bem possível que o servidor em produção **nunca tenha usado o `JWT_SECRET` real do ambiente**, e sim o fallback hardcoded, até este fix). Corrigido trocando `dev`/`start` em `package.json` pra pré-carregar `dotenv/config` via `-r` (`node -r dotenv/config` / `tsx watch -r dotenv/config`), que roda numa fase anterior ao carregamento do módulo de entrada — não sofre do hoisting. **Ação recomendada pro usuário: gerar um `JWT_SECRET` novo em produção** (o valor atual, se nunca foi usado de verdade, pode não ser o que vocês pensam que é — ou pior, pode ser literalmente o fallback antigo que estava no código-fonte público).

## Como ler

- Cada item tem uma tag entre parênteses:
  - **(bug/gap)** — falta de verdade, deveria ser feito.
  - **(fora de escopo)** — adiamento consciente do usuário, não é esquecimento. Não tratar como prioridade sem confirmar antes.
  - **(confirmar)** — incerteza real: pode já estar resolvido, mas não foi verificado no código.
